Claude 和 Codex 都是能帮你写代码、干活的 AI。它们都有**额度**：每段时间能用多少是有上限的，用完就得等几小时，甚至等到下周。

平时自己用，额度用完了，休息一下就好。但如果你让 AI **在后台自动干活**，问题就大了：额度一用完，所有正在做的活一起停下，也没人知道。

我身边一位朋友就遇到了这个问题。他写了一个小程序，专门把各处来的活自动交给 Claude 去做。某天 Claude 的额度快见底了，他想：

**Claude 用不了的时候，能不能让 Codex 自动接着干？**

他做出来了。我读完他的做法，发现最值得学的不是"换个 AI"本身，而是换的时候要注意的几件事。

## 打个比方：白班和夜班

可以把这件事想成两个人轮班：

- **Claude 是白班**，平时活都由它干。
- **Codex 是夜班**，白班下班（额度用完）了，夜班顶上。

换班要做好三件事：

1. **确认白班真的下班了**，不是临时走开一下。
2. **做好交接**：夜班得知道活干到哪了。
3. **守同样的规矩**：白班不许做的事，夜班也不许做。

前两件大家都会想到。**第三件最容易漏，也最危险。**下面一件一件说。

## 一、确认 Claude 真的没额度了

Claude 额度用完时，会返回一句固定的话，比如"已达到 5 小时用量上限"，有时还会带一个表示"请求太多"的错误编号。程序看到这些，就知道 Claude 下班了。

**这里有个坑。**

他一开始的判断条件很宽：只要 Claude 的回复里出现"限流"这个词，就当作 Claude 没额度了。

结果有一次，Claude 在工作报告里写了一句"GitHub 那边被限流了"。说的是别的网站，跟 Claude 自己的额度毫无关系。程序却以为 Claude 下班了，把所有活都转给了 Codex。

后来他改成**只认 Claude 自己说的那几句原话**，误判就没了。

> 判断条件越窄，越不容易冤枉人。

确认 Claude 下班后，程序还会记一张小纸条："Claude 几点以后再用"。时间就写额度恢复的时间。没到点之前，新来的活直接交给 Codex，不用每次都先去试一下 Claude。

## 二、做好交接

活交给 Codex，有三种情况：

| 情况 | 怎么办 |
|---|---|
| 这件活本来就是 Codex 在做 | 继续让 Codex 做完，不来回换 |
| Claude 现在用不了 | 新的活直接交给 Codex |
| Claude 做到一半，额度用完了 | 把这件活交给 Codex，让它接着做 |

第三种最麻烦。比如 Claude 已经改好了一半代码，还提交了一份改动申请（程序员叫它 PR）。Codex 如果不知道这些，从头再来一遍，就会多出一份重复的申请。

他的办法是：**让 Codex 先看交接记录。**

Claude 每次干活，都会把整段对话存在电脑上的一个文件里。程序给 Codex 派活时，在最前面加一句话：

> Claude 之前的对话记录在这个文件里。先读一遍，弄清楚要做什么、做到了哪一步，再接着做。不要重复提交已经提交过的东西。

这就像夜班接班前先翻一下交接本。

## 三、守同样的规矩（最关键）

平时给 Claude 派活，每件活都带着规矩，比如：

- 只是让它查问题的活，**不许改代码**；
- 任何时候都**不许删除整个项目**，**不许强行覆盖别人的代码**；
- 给同事发消息，**必须由本人亲自点发送**，AI 只能写草稿。

如果换成 Codex 时只换了人、没交代规矩，Codex 就成了一个**什么都能做**的 AI。而这恰恰发生在没人盯着的时候。

他把规矩分三层搬了过去。

### 第 1 层：底线，谁来都不许做

删除整个项目、强行覆盖代码这类动作，不管哪件活都禁止。

Codex 可以写一份"禁止清单"，列在上面的命令一律拒绝执行。他把这些底线都写了进去。

### 第 2 层：每件活自己的规矩，原样照抄

给 Claude 派活时，每件活本来就带着一份自己的"不许做"清单。比如"这件活不许提交代码"。

程序把这份清单原样翻译成 Codex 能看懂的版本。这样**同一件活，不管谁来做，能做的事都一样**。

他还专门试过：给 Codex 加上规则后，让它去提交改动申请，Codex 会直接被拒绝。

### 第 3 层：有些规矩跟着工具走，要另外补

这是最隐蔽的一个坑。

"发消息必须本人点发送"这条规矩，在 Claude 那边不是写在清单里的，而是靠 Claude 自带的一个**检查小脚本**拦住的：Claude 每次要动手之前，这个脚本先检查一下，发现要发消息就拦下来。

问题是，**这个小脚本是装在 Claude 身上的，换成 Codex 就没有了。**

就像白班的门禁卡在夜班手里刷不开同一道门。规矩还在，但执行规矩的那个东西，没跟着交接过来。

他的补法很直接：在 Codex 这边**直接禁止操作浏览器和屏幕**，让它根本碰不到发消息的界面。真要发的消息，Codex 把内容写进工作报告，由人自己复制、发送。

### 规矩放在哪，也有讲究

他一开始考虑过两种放法，最后都没用：

- **写进 Codex 的全局设置**：那他自己平时用 Codex 时，也会被这些规矩限制住，很不方便。
- **给夜班单独配一套 Codex 设置，共用同一份登录信息**：Codex 有时会自动更新登录信息，一更新，原来那份就失效了，得重新登录。

最后他把规矩放在一个单独的文件夹里，**只在"夜班"干活时生效**，不影响自己平时使用。

## 四、换班要让人知道

自动换班不能悄悄进行：

- 真的因为额度用完才换成 Codex 时，给本人发一条通知。同一个原因只通知一次，Claude 恢复后自动消掉。
- 在任务列表里，每件活都标出这一轮是谁做的、为什么换。
- 想自己接手时，可以一键回到这件活原来的对话里继续。

## 还做不到的

他也写清楚了几个局限：

- **禁止清单只拦常见写法。** 同一个危险动作换一种写法，清单可能就认不出来了。
- **Codex 少了一层保险。** Claude 遇到危险操作时，还会有一个 AI 再判断一次。Codex 当夜班时，没有这一层。
- **有些工具只有 Claude 有。** 比如他只给 Claude 接了公司聊天软件，Codex 当夜班时就没法帮忙写消息草稿，只能让人自己动手。

## 我学到的三件事

1. **换班不只是换人，规矩要一起交接。** 只换 AI 不搬规矩，等于在最没人盯着的时候，给了它最大的权限。
2. **先弄清楚每条规矩是靠什么执行的。** 有的写在派活清单里，有的靠检查小脚本，有的写在全局设置里。换一个工具，靠旧工具执行的那些规矩就失效了。
3. **判断条件宁可窄一点。** 宽的条件看起来更保险，但只要误判一次，所有活都会被换走。
