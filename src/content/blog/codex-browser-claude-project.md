Codex 和 Claude Code 我每天都用。用了一段时间，我形成了一个很简单的分工：

- **要在网页上替我操作**，比如填表、改在线文档、去别的 AI 网站提问，我交给 **Codex**。
- **要在项目里写代码**，比如改功能、修 bug、按项目的规矩办事，我交给 **Claude**。

这不是什么评测结论，只是我自己的使用感受。下面用两个例子说说原因。

## Codex：像人一样操作网页

### 例子一：改一份在线简历

我有一份简历放在一个在线简历网站上，另外电脑里还有一份更新过的 PDF。我想让网站上的那份和 PDF 保持一致。

手动改的话，要一段一段对照着复制、粘贴、调格式，很烦。我就把网页链接丢给 Codex，说："把这个网页上的简历改成和下载文件夹里那份一样。"

它做了这些事：

1. 在我自己的 Chrome 里打开这个网页。因为是我的浏览器，**本来就是登录状态**，不用重新登录。
2. 读出 PDF 的内容，和网页上的简历逐段对比，找出不一样的地方。
3. 像人一样操作网页：拖动栏目调整顺序、点开编辑框、粘贴带格式的文字、拖动滑块调整照片大小。
4. 改完后截一张图，和原来的 PDF 对比，确认网页显示"已保存"。

最后它还提醒我：换行和间距跟 PDF 有一点差别，照片只存在当前这个浏览器里。

### 例子二：去别的 AI 网站帮我提问

查论文的时候，我想同时问问 GPT Pro 和 Gemini 的"深度研究"。这两个都只能在网页上用，没有给程序调用的接口。

我就让 Codex 去操作：打开网页，选好 Pro 模式，把问题粘贴进去，发送，等它们回答完，再把结果读回来，跟我们自己的分析放在一起对比。

相当于我多了一个助手，帮我在几个网站之间跑腿。

### 为什么它在网页上更顺手

我观察下来，主要有三点：

- **它用的是你自己的浏览器。** 你登录过的网站，它直接就能用，不用另外配置账号。
- **它有两种方式操作网页。** 一种是"看着屏幕点"，跟人一样点按钮、拖东西；另一种是"直接读网页的结构"，能准确找到某个输入框，直接把内容填进去。两种方式配合，遇到复杂的编辑器也不容易卡住。
- **做完会自己检查。** 它会截图，和目标对比，而不是做完就说"好了"。

### 要小心的地方

它在用你登录的账号，**相当于你本人在操作**。它点了"提交"，就真的提交了。

所以我交代任务时会说清楚：只改哪里，哪些按钮不要点。涉及付款、发消息、删除东西的操作，我都要求它先停下来问我。

## Claude：在项目里写代码更靠谱

再说 Claude Code。它其实也能操作浏览器，Chrome 插件和桌面版自带的浏览器都可以。但我觉得它最强的地方在项目里。

### 它会先读规矩，再动手

每个项目都有自己的规矩，比如代码放哪、怎么命名、改完要跑哪些检查。我把这些写在项目根目录的 `CLAUDE.md` 里，Claude 每次开始工作都会先读。

举个例子：这个项目规定"改完要跑类型检查和测试"。Claude 改完代码，会自己去跑；跑不过，会接着修，而不是改完就交差。

### 它能把一件事从头做到尾

这篇博客本身就是一个例子。我只说了一句"帮我写到博客里"，Claude 做了这些事：

1. 找到我博客的源码仓库。
2. 读了之前几篇文章，模仿同样的写法和格式。
3. 写好草稿，在本地构建一遍，确认页面能正常生成。
4. 先给我看草稿，我说"发布"之后才提交、推送。
5. 推送后打开网站检查，确认新文章真的上线了。

每一步都跟前面的事情相关：要知道仓库在哪、之前的文章长什么样、发布要经过我同意。这种需要一直记着上下文、按步骤推进的活，Claude 做得很稳。

### 它能按我的流程走

我还给 Claude 装了一些"技能"，就是写好的固定流程。比如我有一套开发流程：先澄清需求，再出设计，然后写代码、审查、测试，最后上线。每一步做完要过关，才能进下一步。Claude 能照着这套流程一步一步走。

## 我现在的用法

| 事情 | 交给谁 |
|---|---|
| 在网页上填表、改在线文档 | Codex |
| 去 GPT Pro、Gemini 这类网页提问 | Codex |
| 改项目代码、修 bug | Claude |
| 按固定流程推进一个需求 | Claude |
| 代码写完的审查 | 换另一个来审 |

最后一行是我觉得最有用的：**谁写的，就让另一个来审。** 不同的模型盲点不一样，互相检查能发现更多问题。具体怎么在 Claude Code 里直接叫 Codex 来审，可以看我的[上一篇](/blog/claude-code-codex-plugin/)。

两边都在快速更新，这个分工过几个月可能就变了。但现在，这样用最省心。
