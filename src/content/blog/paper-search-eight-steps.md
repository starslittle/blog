最近给毕业论文做查新，一个想法定下来之前，要先确认有没有人做过。

我自认为查得挺全：OpenAlex、Semantic Scholar、arXiv、Crossref、dblp 都查了，还让另一个模型独立再查一遍，最后两边合并。结果还是有几篇关键论文，是方案都写完了才冒出来的，其中一篇直接让一个方向作废。

回头看漏掉的那几篇，发现它们漏得很有规律。

## 漏掉的论文有规律

**一、只用自己的说法搜。** 我搜的是自己给这个想法起的名字。但同一个机制，换个年代、换个领域，叫法完全不同。

举个大家熟悉的例子：今天说"知识蒸馏"（Hinton 等，2015），但"用大模型的输出去训练小模型"这件事，2006 年就有人做过，当时叫"模型压缩"（Model Compression，Buciluă 等）。只搜"蒸馏"，就找不到那篇。

我漏掉的几篇，有的是十年前的老论文，用的是当年的说法；有的是顶会论文，但它把这件事叫成了另一个名字。

**二、引用只往一个方向追。** 我一直在查"谁引用了最接近的那几篇"。可最接近的往往是新论文，被引次数是 0，往后追什么也追不到。真正该追的是它们的**参考文献**，那些老的先例基本都在里面。

**三、每次都从零开始。** 每次查完写一份报告就结束了，没有一份累积的清单。下次再查，说不清上次查过什么、漏了什么，"每周查一次新论文"也就做不起来。

还有一点是复盘时才意识到的：我确实让另一个模型独立查了一遍，但它干的活和我一样，都是搜关键词、读摘要。**真正需要推理的几件事**，比如"这个机制以前叫什么""这两篇是不是同一个东西""我还漏了哪一类"，没有交给推理最强的模型去做。

## 改成八个步骤

每一步都定一个"做到什么程度算完成"，报告里逐步写清楚做了什么、哪里没查到。其中第 1、5、7 步交给推理最强的模型（比如 GPT Pro），其余几步靠 API 检索和人工核对。

### 1. 先写机制描述，再让推理模型列出其他叫法

用两三句话写出想法的**机制**，不用自己起的名字。

然后把它交给 GPT Pro 这类推理最强的模型，让它列出这个机制在不同年代、不同领域可能的叫法：十年前的说法、现在的说法、机器学习里的通用说法、中文文献里的说法。每个说法最好附一篇代表论文，方便下一步验证这个说法是不是真的有人在用。

这一步要靠对文献的广泛了解和推理，API 检索做不了，所以值得用最强的模型。后面所有检索都用这张术语表。**完成标准**：每一类说法至少有一组检索式。

### 2. 多平台检索，按年份分段看

每组检索式在几个平台各跑一次。不要只按日期倒序看最新的，而是分三段看：十年前、近五年、最近一年。

老论文的威胁往往最大，它们决定了"这个问题是不是早就有人提过"。

### 3. 引用往两个方向追

挑 3–5 篇最接近的论文当"种子"：

- **往前追参考文献**：老的先例主要从这里来；
- **往后追被引**：种子被引为 0 时跳过；
- 新找到的高威胁论文当新种子，再追一层，一般两层就够。

注意：OpenAlex 返回的参考文献经常不全，有的论文只解析出一两条。结果很少时，直接打开 PDF 看参考文献列表。

### 4. 把小而集中的会议整本扫一遍

每个细分领域都有几个最集中的会议或期刊。用 dblp 按会议和年份把论文列出来，用第 1 步的词过滤标题，再看摘要。量不大，但命中率很高。

另外可以用 Semantic Scholar 的相似论文推荐，给每个种子拉一批相似论文，补上关键词漏掉的。

### 5. 让推理模型专门找能否定你的论文

把机制描述交给 GPT Pro，问题直接写成"找否定"：

```text
找出已经提出过这个机制、或足以否定它新颖性的已有工作。
每一篇都给出：标题、年份、出处、DOI 或 arXiv ID，
以及原文中说明它做了这件事的那一段话。
另外，有没有机制等价、但名字不同的方法？
```

几个要点：

- **不要附上"我觉得它新在哪里"**。一旦写了，检索就容易被带偏，只去找支持你的证据；
- **要原文段落**，不要只要结论。有原文可以核对，模型也会挖得更深；
- **问"机制等价"**：两个方法写法不同、名字不同，推一步可能就是同一回事。这种关系关键词搜不出来，恰恰是推理模型最擅长的；
- 想一次拉一批候选，可以再用 deep research 补充；另一个模型独立做一遍也有用。

还有一点：如果想法还没公开，交给外部服务时只写到机制层面，不写具体参数和实验设计。

### 6. 查中文文献

中文期刊和学位论文要单独查。往届学位论文里如果有类似的工作，评审最容易注意到，偏偏这一块最容易被跳过。

### 7. 收尾审查：让推理模型检查你漏了什么

前面都做完以后，把机制描述和这次找到的论文列表（标题、年份、出处、威胁程度）一起交给 GPT Pro，问三件事：

1. 还漏了哪一类工作：哪个领域、哪个年代、哪种说法没有查到？
2. 哪篇的威胁被高估或低估了，为什么？
3. 哪几篇其实是同一个机制？

这一步不是再搜一遍，而是**检查覆盖范围**。它指出的漏洞，回到第 2–4 步补查。**完成标准**：它指出的每一处遗漏，都写明"已补查"或"为什么不补"。

### 8. 逐篇核对，再记进清单

所有模型给出的论文都可能是编的，GPT Pro 也不例外。每一篇都要用接口查一下 ID 是否真实存在、标题作者对不对得上：

```bash
# 用 DOI 查（Crossref），会输出这篇论文的标题
curl -s "https://api.crossref.org/works/10.1109/CVPR.2016.90" | jq '.message.title'

# 用 arXiv ID 查，第二个 <title> 是论文标题
curl -sL "https://export.arxiv.org/api/query?id_list=1706.03762" | grep "<title>"
```

核对不了的标"未核实"，不写进结论。读过的论文也标清楚读到哪一步：读了正文、只读了摘要，还是只看到标题。

## 推理模型能做什么、不能做什么

GPT Pro 这类模型负责**找线索、做判断**：换说法、找否定、判断两篇是不是同一个机制、检查覆盖范围。

但**保证搜全、核实真伪**还得靠 API 检索和引用追踪，原因有三个：

- **不能复现**：同一个问题问两次，结果不一样。你说不清它查了哪些范围，报告里的"检索覆盖"就写不出来；
- **会编造**：论文、页码、原文段落都可能是编的，所以必须有第 8 步；
- **只能手动用**：网页版接不进脚本，做不了每周自动的增量查新。

所以两边是互补的：推理模型告诉你该往哪里找，API 和引用追踪保证你真的找过了。

## 用一份清单把每次查新串起来

我现在用一个 CSV 记所有找到的相关论文，一篇一行：

| 列 | 内容 |
|---|---|
| id | DOI 或 arXiv ID |
| title / year / venue | 标题、年份、出处 |
| threat | 威胁程度：高、中、低 |
| verified | 读了正文、摘要，还是只看到标题 |
| found_by | 从哪个渠道找到的：关键词、参考文献、被引、会议扫库、推理模型找否定、收尾审查…… |
| first_seen | 第一次找到的日期 |

有了它：

- **每周增量查新**变得很便宜：把检索式存下来，每周重跑一次，只看清单里没有的；
- `found_by` 这一列能看出哪种渠道最管用，下次优先用。

## 工具踩过的坑

- **Semantic Scholar 经常返回 429**：匿名访问时普通检索接口很容易被限流，改用批量检索接口 `/graph/v1/paper/search/bulk`，或者申请一个免费的 API key；
- **OpenAlex 的参考文献不全**：按引用检索会漏，关键论文要看 PDF；
- **arXiv 不等于全部**：只发期刊的论文、会议短文、只放在 Zenodo 上的材料，arXiv 上都没有；
- **Google Scholar 用脚本基本查不了**，会被拦，只能在浏览器里手动查。它的"被引提醒"倒是很好用，给最接近的几篇论文设上，有人引用就会收到邮件；
- **paper-search MCP 在国内启动超时**：我用 [paper-search-mcp](https://github.com/openags/paper-search-mcp) 一次查多个源。用 `uvx` 启动时，它每次都会重新解析依赖，缓存里缺包就要从 PyPI 下载，国内网络下很容易超过 30 秒的连接时限。解决办法是固定安装成本地工具，启动时就不用联网了：

  ```bash
  uv tool install "git+https://github.com/openags/paper-search-mcp"
  ```

  装完把 MCP 配置里的 `command` 改成 `uv tool dir --bin` 显示的目录下的 `paper-search-mcp`，参数清空。

## 最后

查新的结论永远只能写成"在我查过的范围内，没有发现完全重复的工作"，而不是"这个想法以前没人做过"。没搜到不等于不存在。

能做的，就是让"查过的范围"尽量大，并且把这个范围写清楚。
